# MES2 Master Data CSV Export / Upsert v1

## Purpose
Administrators and IT can download the current table, edit its CSV in Excel, preview an upsert, then explicitly confirm changes in MES Tools Panel. Target tables exclusively `dbo.WorkCenter_Master` and `dbo.Master_Defect_Codes`. No other tables may be written, aside from the dedicated audit table `dbo.MES_MasterDataCSV_Audit` (V0004).

## Endpoints
`POST /api/v1/master-data-csv/export` — `ActorID`, `Password`, `Table` (`WORKCENTER` or `DEFECT`). Returns `CsvText` with exact header and row IDs.

`POST /api/v1/master-data-csv/preview` — above plus `CsvText`. Validates table schema, CSV header, all rows, duplicates, length, existing ID/natural key. Returns `PreviewToken`, INSERT/UPDATE/SKIP summary and first 200 prospective changes. No writes.

`POST /api/v1/master-data-csv/apply` — preview request plus `PreviewToken`. Reauthenticates, takes table lock, rechecks current DB fingerprint, writes UPDATE/INSERT changes and per-row audit *inside one transaction*. Rejects DB/CSV changes since preview. Never deletes.

## CSV data contract
- `WORKCENTER`: `ID,StationType,LineCode` (natural key: `StationType + LineCode`)
- `DEFECT`: `ID,Code,Station,EnglishName,VietnameseName` (natural key: `Code`)
- ID is stable for edits, including renames. For new rows leave ID empty. If ID missing, existing natural key is updated; otherwise inserted.
- Duplicate IDs/keys in CSV are rejected. A new ID not found in DB is rejected. No `IDENTITY_INSERT` is ever used. New IDs generated by SQL Server IDENTITY if configured, otherwise generated as MAX(ID)+1 under an exclusive table lock; this requires an integer ID primary key.
- Removing a row from CSV does **not** delete it. Missing records remain unchanged.
- Exact CSV header and order required. Excel may auto-convert LineCode, Code etc; explicitly set these columns to Text before saving UTF-8 CSV.

## Security
- Backend reauthenticates account password for every export, preview and apply. Only `Emp_Role` Admin/Administrator or `Emp_Dept` IT accepted. Frontend menu filtering is only convenience.
- Existing auth code stores plaintext passwords; this feature does not change it. Deploy behind HTTPS. No password sent in GET URL or included in export/report.
- `MasterDataCSV_Audit` records the actor, timestamp, table, action, and JSON before/after for every changed row. Audit inserts and master-data modifications share one SQL transaction.
- PreviewToken fingerprint guards against accidental concurrent changes; it is not a substitute for account authorization.
- Serialized with `TABLOCKX, HOLDLOCK` during apply, so large imports may temporarily block reads/writes. Apply a tested CSV during maintenance window.

## Schema and deployment
First run `database/sql_updates/V0004__master_data_csv_audit/00_PRECHECK.sql`, then `01_APPLY.sql`, then `02_VERIFY.sql` manually on Dev after DB backup. This updater itself does not execute SQL.

Backend new `app/api/v1/endpoints/master_data_csv.py` and router registration in `app/api/v1/api.py`; FE new `MasterDataCSVView.jsx`, `masterDataCsvAPI.js`, `/master-data-csv` route, and sidebar item. No modifications to the existing `defectcodes.py` or `getWorkCenters` GET API, which continue to read the same tables and will reflect changes on refresh.

## Acceptance test
1. Export both tables, verify UTF-8 and headers.
2. Import unchanged file: `SKIP` all, no database rows modified.
3. Add `LineCode` with blank ID, preview INSERT, apply once, verify `getWorkCenters`.
4. Rename existing line keeping ID, preview UPDATE, verify no duplicate ID.
5. Edit defect English/Vietnamese name, keeping ID, preview UPDATE, verify existing Defect API sees update.
6. Upload duplicate natural key or duplicate ID: reject with clear reason; no writes.
7. Preview then change table in second session: apply must reject stale PreviewToken.
8. Operator outside Admin/IT: Backend returns 403 even if manually calling API.
9. Stop database mid-import or force audit failure: transaction rolls back.
10. Remove a line from CSV and import: database still retains it.

## Limits
- 1 million CSV characters, 2,000 CSV rows per import. For larger tables extend limits only after load tests.
- No automatic deletion or restore from audit yet. Database backup remains necessary.
- Only existing configured table/columns accepted; unexpected schema changes cause 409 instead of guessing.
- SQL Server real transaction and FE build still require manual tests on Dev.
